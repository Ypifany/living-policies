# Living policies

Ypifany’s public working demonstration explains its practical policy service: clear decisions, useful policies, work steps, tool settings, and a way to check whether they help. Working demonstration **0.8**, October 18, 2026.

## Explore

The opening now gives visitors one example and one clear first action before the full work-area and control collection. A draft founder note explains the approach through familiar access, approval, and handoff decisions. The connected gear illustration and interactive example use the same Policy / People / Tools labels.

Open `index.html` in a browser. It is self-contained and needs no installation or external assets.

- **Start here:** a familiar client-approval example has three selectable views: Policy, People, and Tools. Hero actions jump to the demonstration and the founder note. More detailed policy and control connections open on request.
- **Work areas:** six distinct work areas use everyday questions to explain the practical role of policy. Each shows an illustrative policy decision, people’s steps, and technical support, followed by three directly relevant controls and a practical check. Eighteen explicit area-to-control selections explain the connection.
- **See the map:** a graphical map remains visible on phones and desktops. Start with access, sharing, recovery, or AI use. Select a policy, people’s work, tools, the intended result, or review to open an explanation. All 22 control records and 79 control-to-policy connections remain reachable, one control at a time.
- **Policy examples:** eight selected public summaries use plain language for the job a policy supports, example direction, work task, and review question.
- **Work examples:** one anonymized, owner-reported client–developer example and three illustrative situations.
- **Control examples:** open a control from a work area or map. Administrative decisions, people’s actions, and technical support appear together. Dated status, evidence, and standards references remain separate disclosures.

A supporting tool or record is not automatically a technical security safeguard. Some examples protect information or access; others support learning, review, or recovery. The site makes these contributions clear without treating every business practice as an external requirement.

Keyboard buttons, visible focus, live selection announcements, return routes, browser history, and shareable page fragments support navigation. The map height scales with text size and its nodes reflow into two rows on narrower screens.

## Public scope and evidence

Complete Workspace policies and original internal records remain private. Full policy decision lists and internal contribution and setup fields are excluded from the public HTML data as well as the rendered pages. Privacy and refund policies and terms of service have not been drafted here; those website policies will be shown in full when written.

All eight policies are working drafts, not approved. All proposed policy/people/technology setups are illustrative and need to be adapted and checked. Map arrows express intended support, not verified effectiveness. The owner-reported example is anonymized and not independently verified. Illustrative situations do not report client outcomes.

Control IDs, all 79 policy links, statuses, source dates, evidence, status explanations, and external-reference relationships are preserved. Statuses are dated statements from the owner’s workbook, not current independent verification or certification. Draft setups do not confirm every practice or setting is operating. CMMC Level 1 is a voluntary reference; Ypifany has no current DoD contracts. All 15 safeguarding references remain **Not assessed**. No CMMC status or contract eligibility is claimed.

This repository contains only the public demonstration. Client and developer names, email addresses, screenshots, private file IDs, project folder names, account settings, system details, recovery information, and private assessment records are excluded.
